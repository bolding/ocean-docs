manage-analyses Guide

Overview

manage-analyses is the housekeeping tool for the analyses/ output tree. All subcommands default to a dry run — add --apply to actually execute.

Subcommand Purpose
wipe Remove all regeneratable outputs so scripts can be re-run from scratch
purge Completely remove ONE area/experiment — plots, tables, and its statistics.db rows
sync Rsync the remote analyses tree to a local directory
import-stats Import the statistics files into statistics.db (--rebuild: rebuild it from them)
migrate Apply pending layout-version migrations (e.g. v1→v2 scenario-dir reshuffle)

clean was removed — superseded by the separate audit-layout command below, which detects the same non-conforming files using the canonical AnalysesLayout iterators from lib/layout.py and adds --obs-type filtering clean never had.

wipe

Removes all regeneratable outputs — PNG plots and statistics files — from the entire analyses tree so that all validation scripts can be re-run cleanly.

Non-regeneratable content is never touched: - .md narrative files (hand-written area descriptions, experiment notes) - metadata.yaml - simulation_list.db and staging/

# Preview what would be removed
manage-analyses wipe

# Wipe all regeneratable outputs
manage-analyses wipe --apply

Regeneratable patterns removed by wipe:

*_validation_statistics.txt
*_3d_validation_statistics.txt
*_profile_validation_statistics.txt
*_tidal_statistics.txt
*_tidal_detailed_statistics.txt
*_scenario_statistics.txt
gesla_station_comparison.csv
station_comparison.csv
*_validation_statistics.csv
*_trends.txt
**/*.png

purge

Completely removes one (--area, --experiment) pair — plots, tables, and its statistics.db rows — e.g. to clean up a run accidentally made against the wrong area (--area NS when --area NSe was meant). Scoped to exactly that one pair; no other experiment, even in the same area, is touched. Nothing is hard-deleted: everything moves to analyses/.purged/<area>__<experiment>__<timestamp>/ first.

# Preview what would be removed
manage-analyses purge --area NS --experiment CMEMS/v01P

# Actually purge
manage-analyses purge --area NS --experiment CMEMS/v01P --apply

A shared areas/<area>/observations/ directory (station maps, density plots — shared across every experiment in that area) is never touched by purge; it only warns if that directory exists and has content, since removing it could break an unrelated, legitimate experiment in the same area.

Self-relays to the configured relay host automatically if run anywhere else — the real analyses/ tree and statistics.db only live there, same relay mechanism regenerate_hugo.py/deploy_ghpages.py use (~/.config/oceanicu/hosts.yaml, via ocean_data.host_config — see that package's guides/host-config.md) — so it's safe to run purge from anywhere (HPC, a workstation) without remembering where the real data lives. Pass --no-relay to force a genuinely local run instead (e.g. against a different --analyses-dir for testing).

migrate

Applies pending layout-version migrations to a local analyses directory (current version tracked in .layout_version under --analyses-dir, absent = version 1). Dry run by default.

# Preview pending migrations
manage-analyses migrate

# Apply them
manage-analyses migrate --apply

# v1→v2 (moves scenarios/<ssp*>/ under scenarios/<MODEL>/) needs --model
manage-analyses migrate --apply --model GFDL-ESM4

audit-layout (separate tool)

Not a manage-analyses subcommand — a standalone console script (audit-layout, cli/audit_layout.py) that superseded the old clean subcommand. Walks the tree using lib/layout.py's AnalysesLayout iterators, prints every conforming file (optionally filtered to one --obs-type/--area), and lists (or, with --apply, deletes) anything under plots//tables/ that doesn't sit inside the canonical <domain>/<model>/<period-or->/<type>/ structure — then removes any directories left empty by the deletion.

audit-layout --analyses-dir ./analyses
audit-layout --analyses-dir ./analyses --area NS
audit-layout --analyses-dir ./analyses --obs-type argo
audit-layout --analyses-dir ./analyses --apply                    # delete non-conforming
audit-layout --analyses-dir ./analyses --apply --area NS --obs-type argo

sync

Rsyncs the remote analyses tree to a local directory. Only files that conform to the canonical layout are transferred; old-layout artefacts at the wrong directory depth are automatically excluded via rsync filter rules.

# Dry-run sync (shows what would transfer — safe to run first)
manage-analyses sync user@remote:/data/analyses/

# Actual sync
manage-analyses sync user@remote:/data/analyses/ --apply

# Sync to a specific local directory
manage-analyses sync user@remote:/data/analyses/ \
    --analyses-dir /data/local/analyses --apply

# Print the rsync command only (for manual inspection or tweaking)
manage-analyses sync user@remote:/data/analyses/ --print-cmd

# Use a specific SSH key
manage-analyses sync user@remote:/data/analyses/ --apply --ssh ~/.ssh/id_rsa

update-from-remote calls manage-analyses sync internally. Use manage-analyses sync directly when you want to sync without triggering the full report/deploy pipeline.

import-stats

Walks the analyses/ tree and upserts every statistics file into analyses/statistics.db: the *_validation_statistics.yaml sidecars (CSV, or TXT, only where a file has no YAML), tidal statistics, MLE rankings and bias-correction statistics.

# Preview what would be imported (dry run)
manage-analyses import-stats

# Import (a consistent copy statistics.db.bak_<time> is made first)
manage-analyses import-stats --apply

# Rebuild the database from the files alone, replacing statistics.db
manage-analyses import-stats --apply --rebuild

The importer takes area, experiment, domain and model from the experiment's config file or the directory path. Variable names are stored lower case without the layer suffix (SALT_SURFACE and salt are both salt). See the Statistics Database guide for the schema and queries.

--analyses-dir

All subcommands accept --analyses-dir DIR to set the local analyses root. There is no ./analyses fallback: when omitted, the root is expanded from OCEANICU_ANALYSES_FOLDER in this machine's data-roots file (<hostname>_ocean-post_data_roots.yaml). If neither is set, the command stops with an error naming the missing variable — wipe in particular is destructive, so it never guesses a directory from the current path.

Canonical layout reminder

The canonical layout that clean and sync enforce (defined in lib/layout.py):

<analyses_dir>/areas/<AREA>/validations/<EXPERIMENT>/
    plots/<domain>/<model>/<period>/<type>/
    tables/<domain>/<model>/<type>/

Where: - <domain> is physics or bio - <model> is the model name, e.g. pyGETM - <period> is a year (2020) or a range (2015-2022) - <type> is surface, bottom, 3d, argo, tidal, wod, cruise, platform, ices, or a depth slice like 0050m

<EXPERIMENT> itself can be a single name (the legacy layout, still used by NS and AMM7) or <SOURCE>/<experiment> — e.g. CMEMS/tidal, CMIP6_raw/GFDL-ESM4-ssp126/run01 (NSe's layout, selected via --source on the validation scripts). Both forms are recognised by discovery and by clean/sync; see sources.yaml and the tidal/gridded guides for how the --source form is produced.
