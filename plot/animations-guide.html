Animations User Guide

ocean-animations creates time-lapse animations from ocean model NetCDF output. Three animation types are supported, all rendered with Cartopy coastlines and land fill when available.

Type Command Description
map ocean-animations --config map.yaml 2-D horizontal field over time
transect ocean-animations --config transect.yaml x-z or y-z vertical section
comparison ocean-animations --config compare.yaml Model vs observations — same variable, overlaid TS
independent ocean-animations --config indep.yaml Two different variables side by side, separate TS

1. Quick start — init-animation wizard

The wizard probes a NetCDF file and writes a ready-to-run YAML:

init-animation
# → prompts for file, variable, subset, time range, output path
# → writes e.g. sst_map.yaml

ocean-animations --config sst_map.yaml

No flags are needed once the YAML is written.

2. Config format

Every animation file uses a single top-level plottype: key that selects the animation kind — no --type flag needed on the command line.

2.1 Horizontal map

plottype: map

input:
  file: /data/model/sst_daily.nc
  variable: sst
  time_slice:          # optional — frame index range
    start: 0
    end: 365

subset:                # optional — omit for the full domain
  lat_min: 48.0
  lat_max: 65.0
  lon_min: -12.0
  lon_max: 12.0

output:
  # file: sst_ns.mp4  # omit → auto-name from variable long_name
  fps: 15

# title:    # omit → auto-derived from long_name / standard_name
# colormap: # omit → auto-selected from variable metadata (thermal/balance/haline/…)
# vmin:     # omit → data range
# vmax:

2.2 Vertical transect

plottype: transect

input:
  file: /data/model/output_3d.nc
  variable: temp
  time_slice:
    start: 0
    end: 120

transect:
  along: lon           # 'lon' → x-z section  |  'lat' → y-z section
  lat: 55.0            # latitude of the x-z section  (required for along: lon)
  # lon: 5.0           # longitude of the y-z section (required for along: lat)
  z_var: hn            # layer-height variable; omit to auto-detect from coordinates
  z_max: 200           # maximum depth [m]; omit for full water column
  show_grid: false     # true → draw curving sigma-level interface lines
  # grid_color: white  # colour of interface lines (default: white)
  # grid_stride: 2     # draw every N-th line in x and z (default: 1)

output:
  file: temp_xz_55N.mp4
  fps: 4

title: "Temperature x-z transect at 55 °N"
colormap: thermal
vmin: 2.0
vmax: 20.0

2.3 Two-panel comparison

Side-by-side animation — typically model (left) vs observations (right). A horizontal colorbar sits between the maps and any time-series panels.

plottype: comparison

left:
  input:
    file: /data/model/sst_daily.nc
    variable: temp
    time_slice:
      start: 0
      end: 365
  title: "pyGETM SST"
  # vmin:      # per-panel override of the shared vmin
  # vmax:
  # colormap:  # per-panel colormap (overrides top-level)
  # offset:    # additive unit-conversion: value = value * factor + offset
  # factor:    # multiplicative unit-conversion (default 1.0)

right:
  input:
    file: /data/obs/cmems_sst_daily.nc
    variable: analysed_sst
    time_slice:
      start: 0
      end: 365
  title: "CMEMS SST (satellite)"
  offset: -273.15      # K → °C (CCI / CMEMS SST products store Kelvin)

subset:                # applied to both panels
  lat_min: 50.0
  lat_max: 62.0
  lon_min: -5.0
  lon_max: 10.0

output:
  file: sst_model_vs_obs.mp4
  fps: 10

# title: "North Sea SST — Model vs Satellite 2019"
# Omit title to auto-derive: "<left.title> / <right.title>"

colormap: thermal
vmin: 4.0
vmax: 22.0
colorbar: shared       # 'shared' (default) or 'individual'
                       # With 'individual', set vmin/vmax inside left:/right: blocks

# time_sync: index     # 'index' (default) — advance by frame index (equal-length axes);
                       #   warns when paired frames differ in time
                       # 'calendar'        — match by date (different time resolutions);
                       #   left frames with no right frame within the tolerance
                       #   are left out (with a warning)
# time_tolerance_hours: 24   # default: the right dataset's median time step

Colour range notes

  • The range is sampled only from the animated time window (frames within time_slice), not the full dataset. This prevents off-season values from distorting the scale when you animate a winter subset of a year-long file.
  • colorbar: individual gives each panel its own colorbar and its own auto-range (or use left.vmin/left.vmax and right.vmin/right.vmax).
  • offset and factor are applied after the spatial/temporal subset, so they never slow down loading of large files.

Unit conversion example — CCI SST data is stored in Kelvin; to compare directly with a model in °C:

right:
  input:
    file: /data/CCI-SST/2020.nc
    variable: analysed_sst
  offset: -273.15     # K → °C; applied after loading
colorbar: shared      # shared scale now works because both are in °C

2.4 Independent two-panel

Side-by-side animation of two different variables (e.g. temperature and salinity, SSH and SST, model run A vs run B). Each panel has its own colorbar and, optionally, its own time-series subplot below.

plottype: independent

left:
  input:
    file: /data/model.nc
    variable: temp
  title: "Temperature"
  # colormap: thermal      # omit to auto-select
  # vmin: 4.0
  # vmax: 22.0
  timeseries:              # optional — points shown on left TS panel only
    - label: "Station A"
      lat: 57.0
      lon:  5.0
      color: white

right:
  input:
    file: /data/model.nc   # may be same or different file
    variable: salt
  title: "Salinity"
  # colormap: haline
  # vmin: 30.0
  # vmax: 36.0
  timeseries:              # optional — points shown on right TS panel only
    - label: "Station A"
      lat: 57.0
      lon:  5.0
      color: deepskyblue

colorbar: individual       # 'individual' (default) — each panel has its own
# colorbar: shared         # unusual for different variables, but supported

output:
  file: temp_salt.mp4
  fps: 10

Differences from comparison

comparison independent
Intended use Same variable, two sources Different variables
Default colorbar shared individual
timeseries: location Top-level (both panels share) Under left: / right:
TS panel content Both datasets overlaid per panel Each panel shows its own variable

3. Auto-detection

When optional keys are omitted the animation fills them in from the data:

Key omitted What happens
output.file Named <long_name>_map.mp4 (spaces → underscores)
title Set to the variable long_name or standard_name
colormap Selected from variable name / standard_name patterns (see §9)
vmin / vmax Computed from the data range of the first frame

4. Time series panels

Add up to three point-location time series panels below (or to the right of) the map. Each point gets a coloured dot on the map and its own subplot.

ts_layout: below       # 'below' (default) or 'right'

timeseries:
  - label: "St. Malo"
    lat: 48.9
    lon: -1.8
    color: cyan        # optional; defaults cycle through deepskyblue/yellow/lime
  - label: "Wadden Sea"
    lat: 54.0
    lon:  8.5
    color: yellow

For map animations, each panel shows the value at that point over time.

For comparison animations, each panel shows both datasets in the same subplot: a solid line for the left panel and a dashed line for the right panel. A thin faint background trace shows the full animated window; the growing lines advance with the animation. A legend identifies which line is which.

For independent animations, timeseries are configured per panel under left.timeseries / right.timeseries. Each TS subplot shows only its own panel's variable.

Time-axis tick labels adapt automatically to the length of the window — short windows show day-of-month, longer windows show month abbreviations.

5. Layout overrides

All plot types auto-compute figure size and row proportions from the content. Add a layout: block to the YAML to override any of these:

layout:
  figsize: [20, 12]            # [width, height] in inches
  height_ratios: [7, 0.3, 3.5] # row heights — map / colorbar / timeseries
  dpi: 100                     # output resolution

For map animations with ts_layout: right, width_ratios is also supported:

layout:
  figsize: [18, 8]
  width_ratios: [2.5, 1]       # map column / timeseries column
  dpi: 150

The init-animation wizard writes a commented-out layout: block with the auto-computed defaults at the bottom of every generated YAML — uncomment and edit to fine-tune without needing to know the code.

6. Annotations

Geographic annotations can be overlaid on any map. For animations, each annotation can have a time window; outside that window it is invisible.

annotations:

  # ── Text label ──────────────────────────────────────────────────────────────
  - type: text
    lat: 57.0
    lon: 4.0
    text: "North Sea"
    fontsize: 11          # default 10
    color: white          # default white
    ha: center            # left/center/right, default left
    va: bottom            # top/center/bottom, default bottom
    fontweight: normal    # normal/bold, default normal
    bbox:                 # optional background box
      facecolor: black
      alpha: 0.5
      pad: 2
    time_on:  0           # frame index or ISO date "2019-06-01"; omit = always on
    time_off: 100         # omit = stays on once activated

  # ── Point marker (with optional text label) ─────────────────────────────────
  - type: point
    lat: 54.5
    lon: 6.0
    marker: "*"           # default "o"
    markersize: 10        # default 8
    color: red
    label: "Station A"    # optional; creates a text artist next to the marker
    time_on: 30

  # ── Rectangle outline (optionally filled) ───────────────────────────────────
  - type: box
    lat_min: 54.0
    lat_max: 58.0
    lon_min: 3.0
    lon_max: 7.0
    color: yellow
    linewidth: 1.5        # default 1.0
    alpha: 0.8            # default 1.0
    fill: false           # true = semi-transparent fill
    label: ""             # optional text at top-left corner

  # ── Polyline through waypoints ───────────────────────────────────────────────
  - type: line
    points:
      - [55.0, -2.0]
      - [55.0,  8.0]
    color: cyan
    linewidth: 1.0
    linestyle: "--"       # default "-"
    label: "Section A"   # optional; placed at midpoint

  # ── Directed arrow ───────────────────────────────────────────────────────────
  - type: arrow
    from_lat: 55.0
    from_lon: 2.0
    to_lat: 57.0
    to_lon: 4.0
    color: white
    linewidth: 1.5
    label: ""

Time control — time_on and time_off accept either: - An integer (0-based frame index) - An ISO date string ("2019-06-01") — the nearest frame is selected

Static plots (ocean-plot) draw all annotations unconditionally; the time keys are silently ignored.

7. Styling

matplotlib loads its own config hierarchy automatically on import:

  1. System defaults (matplotlibrc bundled with matplotlib)
  2. Per-user: ~/.config/matplotlib/matplotlibrc
  3. Per-project: matplotlibrc in the current working directory (checked into the repo alongside the YAML configs)
  4. Named style sheets: ~/.config/matplotlib/stylelib/

Edit these files directly to control fonts, sizes, DPI, line widths, and everything else matplotlib exposes. No YAML key is needed for this.

The style: key selects a named style (or a .mplstyle path) for a single run, without touching any config files:

style: seaborn-v0_8-paper        # any name accepted by plt.style.use()
style: /path/to/project.mplstyle # or a path to a .mplstyle file

8. CLI flags and overrides

# Config mode — YAML drives all settings; a few flags still apply:
ocean-animations --config map.yaml
ocean-animations --config map.yaml --show-grid           # enable sigma grid
ocean-animations --config map.yaml --grid-color black    # override grid colour

# These flags override the YAML when in config mode:
ocean-animations --config map.yaml --variable tos        # change variable
ocean-animations --config map.yaml --output new.mp4      # change output file
ocean-animations --config map.yaml --title "My title"
ocean-animations --config map.yaml --vmin 0 --vmax 30
ocean-animations --config map.yaml --level 5             # depth level index
ocean-animations --config map.yaml --level bottom        # bottom layer (default: surface)

# Direct mode — no YAML; all flags required:
ocean-animations --input model.nc --variable sst --output sst.mp4
ocean-animations --input model.nc --variable sst --output sst.mp4 \
    --lat-min 50 --lat-max 65 --lon-min -5 --lon-max 10 \
    --fps 15 --cmap haline --vmin 30 --vmax 36

# Interactive HTML (map only, no codec needed):
ocean-animations --input model.nc --variable sst --output sst.html \
    --engine plotly

Full flag reference:

Flag Default Description
--config FILE — YAML config (recommended)
--input FILE — Input NetCDF (direct mode)
--variable VAR — Variable to animate
--output FILE — Output path (.mp4 or .html)
--fps N 10 Frames per second
--level L surface Depth level: surface, bottom or a level index (map animations only)
--cmap NAME thermal Colormap
--vmin / --vmax VAL auto Colour scale limits
--title TEXT auto Figure title
--lat-min/max DEG full domain Spatial subset
--lon-min/max DEG full domain Spatial subset
--type map\|transect map Animation type (direct mode)
--engine matplotlib\|plotly matplotlib Output engine
--along lon\|lat lon Transect axis
--lat / --lon DEG — Transect position
--z-var VAR hn Layer-heights variable
--z-max M full Maximum depth [m]
--show-grid off Sigma-level interface lines
--grid-color COLOR white Grid line colour
--time-slice START:END all Frame index range

9. Python API

from ocean_post.animations import Animator

animator = Animator(engine='matplotlib', verbose=True)

# YAML-driven
animator.create_from_config('animation.yaml')

# Programmatic — horizontal map
import xarray as xr
ds = xr.open_dataset('/data/model_sst.nc')
animator.create_animation_from_data(
    data=ds['sst'],
    output='sst.mp4',
    title='North Sea SST',
    fps=10,
    cmap='thermal',
    vmin=5.0,
    vmax=25.0,
)

# Programmatic — transect
animator.create_transect_animation(
    data=ds['temp'],
    output='temp_xz.mp4',
    along='lon',
    lat=55.0,
    hn=ds['hn'],
    z_max=200,
    cmap='thermal',
    show_grid=True,
)

10. Colormaps

The colormap is auto-selected from variable name and standard_name when colormap: is omitted. Override with any cmocean or matplotlib name.

Variable type Auto-selected colormap
Temperature thermal
Salinity haline
SSH / sea level balance (diverging)
Velocity components u, v balance
Speed / current magnitude speed
Precipitation / runoff rain
Shortwave radiation solar
Oxygen oxy
Chlorophyll algae
Density dense
Bias / anomaly balance
Everything else thermal

11. Sigma coordinates

Transect animations use the model's actual terrain-following sigma levels when layer-height data is available.

With z_var: hn — hn gives the thickness of each layer at each grid point. Cumulative sums from the bottom give actual depths; sigma levels appear as curving lines in depth space.

Without hn — the code looks for a 2-D depth coordinate attached to the variable via the NetCDF coordinates attribute (e.g. zct_av). A 1-D depth coord is broadcast uniformly; as a last resort the layer index is used.

show_grid: true draws sigma-level interface lines. Use grid_stride: N to thin the grid (draw every N-th line) on fine meshes.

12. Troubleshooting

ffmpeg not found

FileNotFoundError: [Errno 2] No such file or directory: 'ffmpeg'

Install ffmpeg and verify with ffmpeg -version.

Colormap "thermal" not available — install cmocean: pip install cmocean.

Empty animation / all-NaN frames — the spatial subset may have excluded all valid data. Run ocean-animations --config map.yaml --verbose and check the reported data ranges against the subset bounds.

Auto-named output ends up in wrong directory — set output.file explicitly or run the command from the directory where the output should land.

Transect shows flat sigma levels — hn is not in the file. Check for an attached depth coordinate or specify z_var: <name>.

Comparison right panel shows constant colour — the observation file may store values in different units (e.g. Kelvin vs °C). Add offset: -273.15 (or the appropriate value) inside the right: block and set colorbar: shared so both panels use the same converted scale.

Comparison colour range includes out-of-season values — if the observation file covers a full year but time_slice selects only winter, the auto-range should already be restricted to those frames. If it is not, set vmin/vmax explicitly.
