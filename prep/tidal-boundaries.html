Tidal + CMIP6 mean boundary conditions

Guide for run-tidal-boundaries — hourly SSH and barotropic transport boundary files for future climate projections.

Overview

For future climate simulations the boundary SSH and barotropic transport are split into two components:

Component Source Frequency
Tidal signal TPXO9 harmonic prediction hourly
Mean (non-tidal) sea level + transport CMIP6 monthly mean hourly (interpolated from monthly)

The output variables (zos, uo, vo) are all on the T-grid (boundary point index nbdyp), consistent with how CMEMS boundaries are structured.

What is added to the TPXO9 tide is set by the optional background section:

background.type Added to the tide Needs
cmip6 (default when the config has a cmip6 section) CMIP6 monthly mean minus its historical mean cmip6:
file zos/uo/vo of a given boundary file, interpolated in time background.file
none (default without cmip6) nothing: the tide alone, as pyGETM computes it online from TPXO9 — 
background:
  type: file
  file: /data/.../my_boundary.nc   # same boundary points (nbdyp), (time, nbdyp) variables
  # variables: {zos: zos_datum_corrected}   # output name -> name in the file (default: same)
  # subtract_mean: true    # add only the file's variability (each point's time mean removed)
  # filename_template: "bdy_2d_tpxo_{start}_{end}.nc"   # default for none/file

The file's points are checked against the boundary point list (count and, when it has boundary_lon/boundary_lat, positions). It may have any time step; outside its period its first/last values are held (with a warning). A variable missing from the file gets the tide alone. From the command line: --tpxo-only or --background-file FILE.

TPXO9 reader

tidal_boundary.py reads TPXO9 constituent files directly with xarray and scipy — no pygetm conda environment is needed. The module is usable in any Python environment that has numpy, xarray, and scipy.

File layout

The TPXO9 atlas directory must contain:

grid_tpxo9_atlas[_v5].nc          # grid file (determines postfix)
h_{name}_tpxo9_atlas_30[_v5].nc   # elevation constituents
u_{name}_tpxo9_atlas_30[_v5].nc   # transport constituents (u and v)

where {name} is one of the 12 supported constituents: m2 s2 n2 k2 k1 o1 p1 q1 mm mf m4 ms4.

If the _v5 grid file exists, all constituent files are also assumed to be _v5 format.

Harmonic prediction

The tidal signal at time t and boundary point j is:

η(t, j) = Σ_n [ Re_n(j) · cos(ω_n · t) − Im_n(j) · sin(ω_n · t) ]

where ω_n are the Doodson angular speeds (degrees per hour) and t is measured in hours since the TPXO reference epoch (1858-11-17 UTC).

Nodal corrections are omitted; the resulting amplitude error is ≲ 3 % over multi-decade spans.

TPXO cache

The tidal signal depends only on the boundary-point coordinates and the time range — it is identical for every CMIP6 model and scenario. The first call saves the result as a compressed NetCDF under tpxo.cache_dir:

tpxo_{variable}_{sha1_12chars}_{start}_{end}.nc

Subsequent calls load the cache, skipping the interpolation and prediction steps. A cache miss happens only when the boundary coordinates or the time range changes.

CMIP6 mean component

For each CMIP6 model and scenario the workflow:

  1. Opens the monthly CMIP6 variable (e.g. zos, uo, vo) using load_cmip6_variable().
  2. Interpolates to the boundary points via RegularGridInterpolator (nearest-neighbour fallback for masked grids).
  3. For 3-D variables (uo, vo): depth-integrates over the water column using centred finite differences for layer thicknesses; NaN cells (below seafloor) contribute zero.
  4. Linearly interpolates monthly values onto the hourly time axis.

Config reference

source_type: tidal_ssh

# ── TPXO9 ────────────────────────────────────────────────────────────────────
tpxo:
  root: /data/TPXO9          # constituent file directory
  cache_dir: /data/TPXO9/cache  # optional; skip to disable caching

# ── CMIP6 ────────────────────────────────────────────────────────────────────
cmip6:
  source_id: MPI-ESM1-2-HR   # CMIP6 model identifier
  experiment_id: ssp370       # scenario
  access: local               # 'local' | 'esgf' | 'pangeo'
  local_root: /data/CMIP6    # only required when access: local
  table_id: [Oday, Omon]      # try daily first, fall back to monthly
  download_if_missing: true   # download from ESGF when local files absent
  esgf_cache_dir: /data/cache/cmip6  # where to cache downloaded files (default: local_root)
  variant_label: r1i1p1f1
  grid_label: gn

# ── Boundary points ──────────────────────────────────────────────────────────
boundary_points:
  file_path: ./bdy_coords/nse_bdy_lonlat.txt
  min_gap_degrees: 0.5        # auto-detect segment boundaries

# ── Time ─────────────────────────────────────────────────────────────────────
time_range:
  start_date: "2015-01-01"
  end_date:   "2100-12-31"
  calendar: standard          # standard | no_leap | all_leap | 360_day

# ── Output ───────────────────────────────────────────────────────────────────
output:
  base_directory: ./boundary_data/nse/tidal
  # default path: CMIP6/{source_id}/{experiment_id}/bdy_2d_{start}_{end}.nc
  # filename_template: "CMIP6/{source_id}/{experiment_id}/bdy_2d_{start}_{end}.nc"

CLI reference

# Full run
run-tidal-boundaries  --config config/nse_tidal_bdy.yaml

# Dry run (print plan without writing files)
run-tidal-boundaries  --config config/nse_tidal_bdy.yaml --dryrun

# Override time range (useful for testing a single year)
run-tidal-boundaries  --config config/nse_tidal_bdy.yaml \
                      --start 2060-01-01 --end 2060-12-31

# Override model, scenario, and output directory
run-tidal-boundaries  --config config/nse_tidal_bdy.yaml \
                      --model UKESM1-0-LL --scenario ssp126 \
                      --output-dir ./boundary_data/nse/tidal

# TPXO9 tide only at the boundary points (no CMIP6)
run-tidal-boundaries  --config config/nse_tidal_bdy.yaml --tpxo-only \
                      --start 2015-01-01 --end 2015-12-31

# TPXO9 tide plus the zos/uo/vo of a boundary file on the same points
run-tidal-boundaries  --config config/nse_tidal_bdy.yaml \
                      --background-file /data/.../my_boundary.nc

Output

One NetCDF file per run, dimensions (time, nbdyp):

Variable Units Description
zos m SSH = TPXO tidal elevation + CMIP6 monthly mean sea level
uo m²/s U barotropic transport = TPXO tidal + CMIP6 depth-integrated uo
vo m²/s V barotropic transport = TPXO tidal + CMIP6 depth-integrated vo
boundary_lon ° Boundary point longitudes
boundary_lat ° Boundary point latitudes
segment_id — Integer segment identifier per boundary point

Notes

  • All variables are on the T-grid (same boundary points for elevation and velocities). GETM handles the u/v staggering internally.
  • No pygetm needed at runtime — the TPXO reader uses only xarray + scipy.
  • Multiple scenarios: run run-tidal-boundaries once per scenario; the TPXO computation is cached after the first run, so subsequent scenarios only recompute the CMIP6 component.
