CMEMS Boundary Conditions Guide

Overview

Downloads and interpolates ocean boundary conditions from the Copernicus Marine Service (CMEMS) onto the model open boundary points.

Command Purpose
check-cmems-coverage Verify dataset extents and masked-halo widths before downloading
run-cmems-boundaries Download and interpolate boundary conditions
boundary-diagnostics QC plots and report for the output files

Requires the [cmems] extra and a Copernicus Marine account:

pip install -e ".[cmems]"
copernicusmarine login

Config structure

# config/mymodel_bdy_create.yaml

setup:
  name: mymodel

boundary_points:
  file_path: "./bdy_coords/mymodel_bdy_lonlat.txt"   # lon lat per line

time_range:
  start_date: "2015-01-01"
  end_date:   "2026-01-01"

processing:
  chunk_size_days: 30
  bbox_buffer: 0.25
  cache_directory: "/data/cache/cmems/bdy"   # null to disable

output:
  base_directory: "./boundary_data/mymodel"
  filename_template: "{dataset_id}_{start_date}_to_{end_date}.nc"

datasets:
  temperature:
    category: physics
    scenarios:
      - dataset_id: "cmems_mod_nws_phy-t_my_7km-3D_P1D-m"
        end_date: "2026-04-30"
      - dataset_id: "cmems_mod_nws_phy-tem_anfc_1.5km-3D_P1D-m"
        start_date: "2026-05-01"
    variables:
      - name: thetao
        output_name: votemper
    depth_range:
      minimum: 0.0
      maximum: 5000.0

Stitching multiple sources in time

Each dataset entry can list multiple scenarios with non-overlapping date ranges. The processor stitches them into a single output file, inserting a transition_date attribute.

Segment overrides

Individual boundary segments can pull from a different source (useful when the primary product has a masked halo over part of the domain):

datasets:
  temperature:
    segment_overrides:
      7:                  # segment index (0-based)
        dataset_id: "cmems_mod_bal_phy_my_P1D-m"
        on_gap: use_default   # fall back to parent if override doesn't cover a period

Workflow

1. Check coverage

check-cmems-coverage --config config/mymodel_bdy_create.yaml
check-cmems-coverage --config config/mymodel_bdy_create.yaml --dataset temperature
check-cmems-coverage --config config/mymodel_bdy_create.yaml --download   # also pre-cache

Reports each dataset's spatial extent, masked-halo width, and whether all boundary points are covered.

2. Dry run

run-cmems-boundaries --config config/mymodel_bdy_create.yaml --dryrun

Runs coverage checks without downloading.

3. Download

run-cmems-boundaries --config config/mymodel_bdy_create.yaml
run-cmems-boundaries --config config/mymodel_bdy_create.yaml --dataset temperature salinity
run-cmems-boundaries --config config/mymodel_bdy_create.yaml --category physics
Option Description
--dataset KEY … Process only these dataset keys
--category CATEGORY … Filter by category (physics, bio)
--download-only Cache data but skip interpolation and file writing
--base-directory DIR Override output directory

4. QC diagnostics

boundary-diagnostics --output-dir ./boundary_data/mymodel --config config/mymodel_bdy_create.yaml

See boundary-diagnostics.md.
