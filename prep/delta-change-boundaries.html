Delta-change boundary conditions

Guide for run-delta-boundaries — future climate boundary files that combine high-resolution AMM7/AMM15 historical data with the CMIP6 climate change signal.

Motivation

Directly using CMIP6 model output as open boundary conditions has two problems:

  1. Coarse resolution — CMIP6 models at 0.25°–1° miss shelf-sea dynamics and may place boundary points in land cells.
  2. Model biases — CMIP6 temperature and salinity can be systematically offset from observations by several degrees / PSU.

The delta-change method solves both by keeping the high-resolution AMM7/AMM15 product as the baseline and adding only the CMIP6 change signal:

corrected(t) = AMM7/AMM15_ref(t_analog)
             + [CMIP6_future_clim(month) − CMIP6_hist_clim(month)]

Result: synoptic variability and spatial structure from the high-resolution reanalysis; long-term climate change trend from CMIP6.

Method details

Reference cycling

t_analog maps each future date to a historical analog:

analog_year = ref_start_year + (future_year − ref_start_year) % n_hist_years

February 29 in a leap year maps to February 28 when the analog year is not a leap year. The same day-of-year and hour are preserved.

CMIP6 change signal

For each CMIP6 model and scenario:

  1. Compute hist_clim(month) — monthly climatology of the variable over cmip6.hist_period from the historical experiment.
  2. Compute fut_clim(month) — monthly climatology over cmip6.future_period from the scenario experiment.
  3. delta(month) = fut_clim(month) − hist_clim(month) — the change signal.

For 3-D variables (thetao, so) the delta has shape (12, n_depth_cmip6, n_pts). It is remapped from CMIP6 depth levels onto the AMM7/AMM15 depth levels with linear interpolation before being added to the reference data.

For 2-D variables (zos) or depth-integrated variables (uo, vo): delta has shape (12, n_pts).

Time interpolation

The monthly delta is linearly interpolated onto the reference dataset's time axis (daily for T/S, hourly for SSH/transport) before addition.

Config reference

source_type: cmip6_delta_change

# ── High-resolution historical reference ─────────────────────────────────────
reference:
  directories:
    # per-variable paths to boundary NetCDF directories
    thetao: ./boundary_data/nse/daily
    so:     ./boundary_data/nse/daily
    zos:    ./boundary_data/nse/hourly
    uo:     ./boundary_data/nse/hourly
    vo:     ./boundary_data/nse/hourly
  period:
    start: "1993-01-01"   # start of the cycling reference period
    end:   "2022-12-31"   # end   of the cycling reference period

# ── CMIP6 change signal ───────────────────────────────────────────────────────
cmip6:
  source_id: MPI-ESM1-2-HR
  experiment_id: ssp370      # default scenario; override with --scenario
  access: local              # 'local' | 'esgf' | 'pangeo'
  local_root: /data/CMIP6
  table_id: Omon
  variant_label: r1i1p1f1
  grid_label: gn

  hist_period:               # period for historical climatology
    start: "1985-01-01"
    end:   "2014-12-31"

  future_period:             # period for future climatology
    start: "2070-01-01"
    end:   "2099-12-31"

# ── Variables ─────────────────────────────────────────────────────────────────
variables:
  - name: thetao             # output variable name
    cmip6_var: thetao        # CMIP6 variable name
    table_id: Omon           # override cmip6.table_id if needed
    frequency: daily         # reference data frequency: daily | hourly

  - name: so
    cmip6_var: so
    table_id: Omon
    frequency: daily

  - name: zos
    cmip6_var: zos
    table_id: Omon
    frequency: hourly

  - name: uo
    cmip6_var: uo
    table_id: Omon
    depth_integrate: true    # depth-integrate 3-D → 2-D transport
    frequency: hourly

  - name: vo
    cmip6_var: vo
    table_id: Omon
    depth_integrate: true
    frequency: hourly

# ── Output time range (the projected period to produce) ───────────────────────
time_range:
  start_date: "2015-01-01"
  end_date:   "2100-12-31"
  calendar: standard

# ── Output ────────────────────────────────────────────────────────────────────
output:
  base_directory: ./boundary_data/nse/delta_change
  filename_template: "delta_{source_id}_{experiment_id}_{variable}_{start}_{end}.nc"

CLI reference

# Full run (all variables, default scenario)
run-delta-boundaries  --config config/nse_delta_bdy.yaml

# Dry run
run-delta-boundaries  --config config/nse_delta_bdy.yaml --dryrun

# Process only specific variables
run-delta-boundaries  --config config/nse_delta_bdy.yaml --variable thetao so

# Run multiple scenarios
run-delta-boundaries  --config config/nse_delta_bdy.yaml \
                      --scenario ssp126 ssp245 ssp370 ssp585

# Override future period (e.g. near-term projection)
run-delta-boundaries  --config config/nse_delta_bdy.yaml \
                      --future-start 2040-01-01 --future-end 2059-12-31

Output

One NetCDF file per variable + scenario combination, dimensions (time, nbdyp) or (time, nbdyp, depth) for 3-D variables:

Variable Dims Description
thetao time, nbdyp, depth Potential temperature
so time, nbdyp, depth Practical salinity
zos time, nbdyp Sea surface height
uo time, nbdyp Barotropic eastward transport (m²/s)
vo time, nbdyp Barotropic northward transport (m²/s)

The output NetCDF includes global attributes recording the reference period, CMIP6 model, scenario, and delta-change parameters.

Notes

  • Reference period: choose 20–30 years that have stable, high-quality AMM7 or AMM15 reanalysis coverage. The 1993–2022 period works well for the NSe setup.
  • Future period: a 20–30 year window centred on the epoch of interest averages out internal variability in the CMIP6 change signal.
  • Multiple scenarios: specify --scenario ssp126 ssp370 ssp585 to process all in a single call.
  • Combining with tidal: the delta-change output for SSH/transport and the tidal boundary output are complementary — use tidal + CMIP6 mean for the hourly signal and delta-change for the low-frequency daily/monthly variability if separate hourly tidal forcing is not needed.
  • Depth level mismatch: CMIP6 depth levels are typically coarser than AMM7/AMM15. _remap_delta_depth() handles the remapping with linear interpolation, so no preprocessing of CMIP6 data is required.
