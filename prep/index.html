ocean-prep

Ocean model input preparation — bathymetry, boundary conditions, and initial conditions. Provides a unified CLI and Python API for the three tasks needed before running a regional ocean model:

Task CLI commands Config file
Bathymetry bathymetry-regrid, bathymetry-create-grid, bathymetry-splice <model>_bathy_create.yaml
Boundary conditions (historical) run-cmems-boundaries, run-cmip6-boundaries <model>_bdy_create.yaml
Boundary conditions (future — tidal+CMIP6) run-tidal-boundaries <model>_tidal_bdy.yaml
Boundary conditions (future — delta-change) run-delta-boundaries <model>_delta_bdy.yaml
Initial conditions download-init-conditions <model>_init_create.yaml
Bias correction bc correct, bc diagnostics, bc check bc_correct_example.yaml

For the full ocean-* toolkit, install via ocean-stack rather than this package alone. ocean-stack sets up all four packages in a single conda environment — the recommended route because xesmf/esmpy, used here for bathymetry regridding and bias correction, must come from conda-forge and cannot be reliably pip-installed. Use the standalone installation below only if you need this package in isolation. The full cross-package CLI reference is at ocean-stack/guides/cli-reference.md.

Part of the ocean-* family: ocean-data · ocean-plot · ocean-prep · ocean-post

Installation

xesmf requires esmpy which must come from conda-forge — this is a family-wide constraint shared with ocean-post. The recommended setup is therefore conda:

# Clone sibling packages first
git clone ... ocean-data
git clone ... ocean-plot
git clone ... ocean-prep

cd ocean-prep
conda env create -f environment.yml
conda activate ocean-prep

environment.yml pip-installs ocean-data, ocean-plot, and ocean-prep itself in editable mode (-e), so changes to any of the three repos are immediately visible without reinstalling.

Optional extras

Uncomment the relevant lines in environment.yml before creating the environment, or install after activation:

pip install copernicusmarine          # CMEMS / Copernicus Marine download
pip install intake-esgf esgf-pyclient # CMIP6 via ESGF
pip install -e ".[bc]"                # bias correction (xesmf + copernicusmarine; needs conda esmpy)

pip-only (no xesmf)

If you don't need conservative bathymetry regridding you can skip conda:

pip install -e ../ocean-data
pip install -e ../ocean-plot
pip install -e .
pip install -e ".[cmems]"    # add CMEMS download
pip install -e ".[plot]"     # add cartopy + cmocean (map plots)

Model setup workflow

The intended pattern is one directory per model, containing a config/ subfolder with the three YAML files. Interactive wizards create the initial configs:

mkdir mymodel && cd mymodel

init-bathymetry           # → config/mymodel_bathy_create.yaml
init-boundaries           # → config/mymodel_bdy_create.yaml
init-initial-conditions   # → config/mymodel_init_create.yaml

Then run each pipeline from that directory:

bathymetry-regrid            --config config/mymodel_bathy_create.yaml
run-cmems-boundaries         --config config/mymodel_bdy_create.yaml
download-init-conditions     --config config/mymodel_init_create.yaml --source AMM7

Bathymetry

Reads a high-resolution source (GEBCO, EMODnet) and regrids it conservatively onto the model target grid. Produces a NetCDF bathymetry file and a Markdown report with diagnostic plots.

# Interactive config wizard
init-bathymetry

# Run the pipeline
bathymetry-regrid  --config config/mymodel_bathy_create.yaml
bathymetry-regrid  --config config/mymodel_bathy_create.yaml --dryrun

# Generate a curvilinear supergrid (for rotated-pole or curvilinear models)
bathymetry-create-grid  --config config/mymodel_grid_create.yaml

Config key fields:

source: /data/GEBCO_2023.nc      # or emodnet
grid:
  lon_min: -5.0
  lon_max: 15.0
  lat_min: 47.0
  lat_max: 62.0
  dlat: 0.1
regridding:
  min_depth: 2.0
smooth:
  rx0: 0.2
output:
  file: bathy_mymodel.nc
  report_dir: ./report/mymodel

Boundary conditions

CMEMS (Copernicus Marine) — historical

Downloads T, S, U, V, SSH from the NWS AMM7 or AMM15 reanalysis / ANFC products and writes NEMO-compatible boundary NetCDF files, one per variable.

init-boundaries                                              # create config
check-cmems-coverage  --config config/mymodel_bdy_create.yaml
run-cmems-boundaries  --config config/mymodel_bdy_create.yaml --dryrun
run-cmems-boundaries  --config config/mymodel_bdy_create.yaml
boundary-diagnostics  --output-dir ./boundary_data/mymodel \
                      --config config/mymodel_bdy_create.yaml

CMIP6 — historical and near-future

Downloads and interpolates CMIP6 model data onto boundary points.

check-cmip6-coverage  --config config/mymodel_bdy_create.yaml
run-cmip6-boundaries  --config config/mymodel_bdy_create.yaml

Future projections — tidal + CMIP6 mean (run-tidal-boundaries)

Produces hourly SSH and barotropic transport boundary files for future climate projections. Combines:

  • TPXO9 tidal prediction (elevation + transports) — read directly from the TPXO9 constituent NetCDF files with pure Python (xarray + scipy); no pygetm conda environment needed.
  • CMIP6 monthly mean SSH / depth-integrated transport (zos, uo, vo) from a specific model + scenario.
zos(t)  = TPXO9 tidal η(t)  +  CMIP6 monthly zos        → hourly
uo(t)   = TPXO9 tidal U(t)  +  CMIP6 monthly ∫uo·dz     → hourly
vo(t)   = TPXO9 tidal V(t)  +  CMIP6 monthly ∫vo·dz     → hourly

The tidal prediction is cached per boundary-grid + time-range so it is computed only once, regardless of how many CMIP6 models or scenarios are run.

Instead of the CMIP6 mean, the tide can be combined with the zos/uo/vo of a given boundary file (--background-file, background.type: file) or written alone (--tpxo-only, background.type: none); see guides/tidal-boundaries.md.

run-tidal-boundaries  --config config/mymodel_tidal_bdy.yaml
run-tidal-boundaries  --config config/mymodel_tidal_bdy.yaml --dryrun
run-tidal-boundaries  --config config/mymodel_tidal_bdy.yaml \
                      --start 2060-01-01 --end 2060-12-31

Config key fields (source_type: tidal_ssh):

source_type: tidal_ssh
tpxo:
  root: /data/TPXO9            # directory with h_*.nc and u_*.nc constituent files
  cache_dir: /data/TPXO9/cache # shared TPXO cache across scenarios/models
cmip6:
  source_id: MPI-ESM1-2-HR
  experiment_id: ssp370
  access: local
  local_root: /data/CMIP6
  table_id: Omon
  variant_label: r1i1p1f1
  grid_label: gn
boundary_points:
  file_path: ./bdy_coords/nse_bdy_lonlat.txt
time_range:
  start_date: "2015-01-01"
  end_date:   "2100-12-31"
  calendar: standard
output:
  base_directory: ./boundary_data/nse/tidal
  filename_template: "tidal_{source_id}_{experiment_id}_{start}_{end}.nc"

See config/nse_tidal_bdy.yaml for a fully annotated example.

Future projections — delta-change (run-delta-boundaries)

Produces boundary files that preserve high-resolution AMM7/AMM15 structure while adding the CMIP6 climate change signal:

corrected(t) = AMM7/AMM15_ref(t_analog)
             + [CMIP6_future_clim(month) − CMIP6_hist_clim(month)]

t_analog cycles through the historical reference period (same day-of-year and hour, year mapped modulo the reference period length). Works for T, S (3-D, monthly delta per depth level) and SSH/transport (2-D, optional depth-integration).

This approach eliminates CMIP6 mean biases entirely while preserving synoptic variability and spatial structure from the high-resolution reanalysis.

run-delta-boundaries  --config config/mymodel_delta_bdy.yaml
run-delta-boundaries  --config config/mymodel_delta_bdy.yaml --dryrun
run-delta-boundaries  --config config/mymodel_delta_bdy.yaml --variable thetao so
run-delta-boundaries  --config config/mymodel_delta_bdy.yaml \
                      --scenario ssp126 ssp245 ssp370 ssp585
run-delta-boundaries  --config config/mymodel_delta_bdy.yaml \
                      --future-start 2070-01-01 --future-end 2099-12-31

Config key fields (source_type: cmip6_delta_change):

source_type: cmip6_delta_change
reference:
  directories:
    thetao:  ./boundary_data/nse    # daily/hourly files sit flat in the same dir now
    so:      ./boundary_data/nse
    zos:     ./boundary_data/nse
    uo:      ./boundary_data/nse
    vo:      ./boundary_data/nse
  period:
    start: "1993-01-01"
    end:   "2022-12-31"
cmip6:
  source_id: MPI-ESM1-2-HR
  experiment_id: ssp370
  hist_period:
    start: "1985-01-01"
    end:   "2014-12-31"
  future_period:
    start: "2070-01-01"
    end:   "2099-12-31"
variables:
  - name: thetao
    cmip6_var: thetao
    table_id: Omon
    frequency: daily
  - name: uo
    cmip6_var: uo
    table_id: Omon
    depth_integrate: true
    frequency: hourly

See config/nse_delta_bdy.yaml for a fully annotated example and guide below.

Boundary diagnostics

Generates QC plots and a REPORT.md from the produced boundary NetCDF files:

Plot Content
map_<var>.png Boundary points coloured by segment; NaN points flagged
timeseries_<var>.png Segment-mean surface (solid) and bottom (dashed) time series
hovmoller_<var>.png Hovmöller (time × boundary index) at the surface
profiles_<var>.png Mean depth profiles per segment
seams_<var>.png Stitching-seam zoom (opt-in with --check-seams)

The bottom time series uses each boundary point's geographically-fixed bottom depth (last depth level that is non-NaN at all time steps), averaged across the segment.

# Single output directory
boundary-diagnostics  --output-dir ./boundary_data/mymodel \
                      --config config/mymodel_bdy_create.yaml \
                      --check-seams

# Combine hourly + daily in one report
boundary-diagnostics  --output-dir ./boundary_data/mymodel/hourly \
                                   ./boundary_data/mymodel/daily \
                      --labels 1h 1d

Initial conditions

Downloads 3-D T and S snapshots from NWS AMM7 (MY reanalysis) or AMM15 (ANFC) covering the model bounding box. A Baltic fallback source fills the Kattegat / Belt Sea region where NWS products have a land mask.

init-initial-conditions                                          # create config

# Coverage check
download-init-conditions  --config config/mymodel_init_create.yaml \
                          --source AMM7  --check-coverage

# Download (dryrun first)
download-init-conditions  --config config/mymodel_init_create.yaml \
                          --source AMM7  --dryrun
download-init-conditions  --config config/mymodel_init_create.yaml \
                          --source AMM7

# AMM15 ANFC (2024-03-01 onwards)
download-init-conditions  --config config/mymodel_init_create.yaml \
                          --source AMM15  --year 2025

# IC diagnostics
ic-diagnostics  --output-dir ./init_data/mymodel
ic-diagnostics  --output-dir ./init_data/mymodel \
                --diag-dir ./init_data/mymodel/diagnostics

Config key fields:

domain:
  lon_min: -8.0
  lon_max: 13.0
  lat_min: 47.5
  lat_max: 62.0
flood_fill: true      # fill land-masked cells for model interpolation
sources:
  AMM7:
    year: 2015
    datasets:
      temperature:
        sources:
          - dataset_id: "cmems_mod_nws_phy-t_my_7km-3D_P1D-m"
            priority: 1
          - dataset_id: "cmems_mod_bal_phy_my_P1D-m"
            priority: 0
        variables: [{name: thetao}]

Bias correction

Bias-correct CMIP6 atmospheric forcing files against an observational reference (ERA5 or equivalent) using Quantile Delta Mapping, Quantile Mapping, or Delta methods.

# Check data availability before running
bc check        --config config/bc_correct_example.yaml

# Apply bias correction (all variables in config)
bc correct      --config config/bc_correct_example.yaml
bc correct      --config config/bc_correct_example.yaml --variable tas pr
bc correct      --config config/bc_correct_example.yaml --scenario ssp585
bc correct      --config config/bc_correct_example.yaml --model CNRM-ESM2-1

# Inspect correction quality
bc diagnostics  --config config/bc_correct_example.yaml
bc diagnostics  --config config/bc_correct_example.yaml --variable tas --output-dir ./diag/

A full annotated config is in config/bc_correct_example.yaml.

NSe example configs

Ready-to-run configs for the North Sea–Baltic (NSe) model are in config/:

config/nse_bdy_create.yaml     # CMEMS boundaries for NSe
config/nse_init_create.yaml    # initial conditions for NSe (AMM7 MY + AMM15 ANFC)
config/nse_tidal_bdy.yaml      # tidal + CMIP6 mean hourly boundaries for NSe
config/nse_delta_bdy.yaml      # delta-change boundaries for NSe

The NSe boundary coordinate file is the canonical copy in OceanICU/oceanicu_3d/NSe/Bathymetry/nse_bdy_lonlat.txt (see that repo's NSe/BOUNDARY_GENERATION.md), referenced by each NSe config's boundary_points.file_path as a real absolute path — not a copy under ocean-prep/bdy_coords/, and not a symlink either (every setup has its own canonical copy under its own repo; a shared symlink target doesn't generalize across setups). Every other domain setup follows the same pattern: its own boundary-point file lives in its own repo, referenced directly by that setup's own configs. All commands are run from the ocean-prep/ root:

# Historical boundaries
check-cmems-coverage   --config config/nse_bdy_create.yaml
run-cmems-boundaries   --config config/nse_bdy_create.yaml --dryrun
run-cmems-boundaries   --config config/nse_bdy_create.yaml
boundary-diagnostics   --output-dir ./boundary_data/nse \
                       --config config/nse_bdy_create.yaml

# Future boundaries — tidal
run-tidal-boundaries   --config config/nse_tidal_bdy.yaml

# Future boundaries — delta-change (T, S, SSH, transport)
run-delta-boundaries   --config config/nse_delta_bdy.yaml
run-delta-boundaries   --config config/nse_delta_bdy.yaml --scenario ssp126 ssp370 ssp585

# Initial conditions
download-init-conditions  --config config/nse_init_create.yaml \
                          --source AMM7  --dryrun
download-init-conditions  --config config/nse_init_create.yaml --source AMM7
download-init-conditions  --config config/nse_init_create.yaml --source AMM15

# IC diagnostics
ic-diagnostics  --output-dir ./init_data/nse
